# QLion Gemma 4 학습 및 어댑터 설계

상태: 제안. 이 문서는 구현 완료를 뜻하지 않는다. 대상은 `llama-finetune-qlion`의 양자화된 기본 웨이트 학습과 Gemma 4 26B A4B 검증이다. QLion2를 QLoRA 옵티마이저로 추가하거나 FP32 LoRA 어댑터의 QAT 및 어댑터 resume을 구현하는 작업은 범위 밖이다.

## 현재 상태

- `--qat-targets`는 이미 QLion에서 양자화 텐서 이름의 부분 문자열로 학습 대상을 제한한다. `--freeze-layers`는 현재 QLoRA 전용이다. 대상 필터는 `examples/qlora_training/finetune_qat.cpp`에 있다.
- QLion은 현재 모델 전체 GGUF를 저장한다. 주기 체크포인트는 별도의 `.qat-state.gguf`에 옵티마이저 상태와 학습 위치를 저장한다. 최종 모델에는 이 상태가 없다.
- `MUL_MAT_ID`의 backward와 QLion의 sparse row/전문가 관련 경로가 일부 존재한다. 따라서 MoE backward 전체가 없다고 가정하지 말고 연산, 형식, 백엔드, 실제 모델별로 지원 여부와 수치 정확도를 확인한다.
- KV 학습을 위한 `SET_ROWS` backward 경로가 있으나 과거 캐시 행은 분리되어 있다. `attn_k`, `attn_v`의 학습 가능 여부는 사용한 KV 경로와 그래프에 따라 검증해야 한다. 기본 설정에서 두 파라미터 모두 유효한 gradient를 받는다고 가정하지 않는다.
- 일반 optimizer에는 static graph 지원이 있지만 현재 llama 학습 경로의 KV 길이와 마스크 형상은 마이크로배치에 따라 달라진다. 단순히 static 플래그를 켜는 방식으로 해결되지 않는다.

## 학습 대상 선택

기존 `--qat-targets`를 유지해 학습 가능한 양자화 텐서의 이름을 선택한다. QLion에도 `--freeze-layers N`을 제공해 `blk.0`부터 `blk.N-1`까지 제외한다. 두 조건은 교집합이며 임베딩, 출력 등 레이어 외 텐서는 이름 필터로 별도 선택한다. 음수, 레이어 수를 초과하는 값, 지원되지 않는 타입 또는 선택 결과가 0개인 경우에는 명확히 오류를 출력한다. 필터의 기존 부분 문자열 의미를 유지한다. tied embedding/output을 감지하면 `token_embd`는 기본 대상에서 제외한다. 명시적으로 포함하면 전체 어휘에 대한 dense gradient 및 예상 어댑터 크기를 경고한다.

실제 등록된 이름, 타입, 형상, 텐서 수와 바이트 수를 출력한다. 추정 메모리는 선택한 텐서를 기준으로 계산하고, 공유 또는 tied 텐서는 한 번만 계산한다. 비학습 가중치의 gradient와 옵티마이저 상태는 만들지 않는다. 다만 선택한 앞쪽 텐서에 gradient를 전달하는 데 필요한 활성값 gradient는 유지한다.

## QLion 어댑터 GGUF

어댑터는 LoRA 차분이 아니라 **학습 후 양자화된 텐서의 대체값**이다. v1은 원본과 실제 바이트가 다른 텐서만 원래 양자화 타입과 형상으로 전체 저장한다. 옵티마이저 update가 일어나도 residual이 양자화 경계를 넘지 않아 바이트가 같을 수 있으므로 update 횟수로 포함 여부를 결정하지 않는다. dirty 비트는 비교 후보를 줄이는 데 사용할 수 있지만 최종 원본 바이트 비교로 확정한다. 전체 텐서를 저장하므로 크기는 선택한 변경 텐서의 전체 크기이며, 26B A4B의 전문가 gate-up/down은 GB 단위가 될 수 있다. 저장 전 예상 및 실제 크기를 출력한다.

GGUF 텐서 디렉터리를 텐서 이름, 타입, 형상, 오프셋 인덱스로 사용한다. 포맷 식별자와 버전, 기본 모델 아키텍처, 학습 대상 및 생성 정보, 기본 모델 전체 SHA-256과 대체 텐서별 원본 바이트 SHA-256을 기록한다. 원본은 학습 시작 시점의 양자화 바이트다. tied 텐서는 물리 저장소와 논리 이름의 관계를 기록하고 동일 저장소를 중복 교체하지 않도록 검증한다. 해시는 학습 전 스냅샷 또는 갱신 전에 계산해야 하며 이후 변경된 웨이트로 계산해서는 안 된다.

v1은 전체 텐서만 저장하지만 텐서별 선택적 `rows`와 `experts` 인덱스 필드 및 표현 종류를 예약한다. 필드 부재는 전체 대체를 뜻한다. 정렬된 중복 없는 인덱스, 인덱스 범위, 원본 형상, 페이로드 순서, 행과 전문가 단위 해시 및 겹침의 의미는 부분 대체를 구현하기 전에 규정한다. v1 판독기는 자신이 지원하지 않는 부분 대체를 거부한다. 양자화 행과 전문가 슬라이스는 블록 정수 배일 때 바이트 단위 교체가 가능하다. v1의 전체 텐서 제한은 구현 단순화를 위한 것이며 블록 경계가 원천적인 장애라는 뜻은 아니다. 향후 부분 대체에서는 변경된 행/전문가의 원본과 학습 후 바이트를 비교하여 실제로 다른 부분만 기록한다.

전체 파일 해시는 1차 식별자로 사용한다. 해시 결과는 파일 정체성 및 크기, 수정 시간 등으로 무효화하는 캐시에 저장할 수 있으나, 캐시만을 신뢰 근거로 삼지 않는다. 전체 해시가 일치하지 않아도 명시적 호환성 검사 경로에서 아키텍처, 모든 대체 대상의 이름/타입/형상 및 원본 텐서 해시가 일치하면 메타데이터만 다른 모델을 허용할 수 있다. 비대상 텐서가 다를 수 있으므로 전체 모델의 동등성은 보장하지 않고 경고한다. 전체 해시가 일치하는 경우에도 대상 텐서 해시를 검사한다. split GGUF는 v1에서 거부하며 경로명만으로 호환성을 판단하지 않는다.
학습이 끝날 때 임시 파일에 쓰고 성공하면 이름을 바꾼다. 저장 실패 시 기존 어댑터를 손상시키지 않는다. GGUF를 읽을 때 메타데이터 타입, 중복 이름, 크기 연산 오버플로, 텐서 범위, 지원 타입과 예상 데이터 길이를 검사한다. 옵티마이저 상태, 데이터셋 위치, 스케줄러는 이 추론/병합용 어댑터에 포함하지 않는다. 기존 전체 모델 체크포인트와 `.qat-state.gguf` 재개 경로는 그대로 둔다.

### 부분 대체 포맷 계약

후속 포맷은 `qlion.adapter.version = 2`, `qlion.adapter.layout = "units"`를 사용한다. v1은 그대로 유지하며 v1 판독기는 v2를 거부한다. v2의 각 GGUF 텐서 이름과 양자화 타입은 기본 모델과 같고, 디렉터리 순서의 인덱스 `i`에 대해 다음 메타데이터를 둔다.

- `qlion.adapter.tensor.<i>.shape`: 기본 텐서의 GGML 차원 순서 `[ne0, ne1, ne2, ne3]`를 담은 UINT64 배열.
- `qlion.adapter.tensor.<i>.rows` 또는 `qlion.adapter.tensor.<i>.experts`: 둘 중 정확히 하나인 UINT64 배열. 인덱스는 오름차순이며 중복과 빈 배열을 금지한다.
- `qlion.adapter.tensor.<i>.base_unit_sha256`: 인덱스 순서대로 각 원본 단위의 바이트 SHA-256을 담은 문자열 배열.
- 기존 `qlion.adapter.tensor_payload_sha256`: 텐서 디렉터리 순서의 전체 페이로드 SHA-256 문자열 배열.

행 인덱스는 `row = i1 + ne1 * (i2 + ne2 * i3)`이며 범위는 `0 <= row < ne1 * ne2 * ne3`이다. 각 행은 `ggml_row_size(type, ne0)` 바이트다. 행 페이로드 텐서는 `[ne0, 행 수, 1, 1]`이며 배열 순서대로 원본 행의 바이트를 붙인다. 전문가 인덱스는 `ne2` 축이며 전문가별로 `ne0 * ne1` 요소를 담는다. v2 전문가 표현은 `ne3 == 1`인 텐서에만 허용하고 페이로드 형상은 `[ne0, ne1, 전문가 수, 1]`이다. 각 단위의 원본 및 변경 여부는 해당 연속 바이트를 직접 비교한다. `ne0`가 양자화 블록 크기의 배수인지, 모든 차원과 곱셈, 오프셋, 페이로드 길이가 유효한지 파일 값을 사용한 연산 전에 검사한다.

독립 어댑터의 각 단위를 기본 파일의 바이트 구간으로 바꾸어 정렬한 후 겹침을 검사한다. 전체 텐서 v1은 텐서 전체 구간이며 행과 전문가 단위는 각자의 구간이다. 논리 이름이 달라도 물리 구간이 겹치면 거부한다. 입력 어댑터 순서에 관계없이 원본 단위 해시와 페이로드 해시를 먼저 검증한다. 전체 파일 해시 불일치는 기존 명시적 허용 옵션에서만 허용하며 모든 대체 단위의 원본 해시는 여전히 필요하다. 변경되지 않은 단위는 출력에 포함하지 않는다.

병합기는 기본 파일 복사본의 검증된 구간에 페이로드 단위를 쓰고 원자적으로 확정한다. 런타임은 기본 텐서를 backend buffer에 스트리밍한 후 검증된 단위들을 해당 바이트 오프셋에 덮어쓴다. 검증부터 복사까지 파일이 바뀌는 경우를 막기 위해 복사되는 페이로드를 다시 해시하고, 기본 파일의 식별자도 전후에 확인한다. mmap으로 부분 수정한 데이터가 원본 파일에 기록되거나 다른 모델에 노출되어서는 안 된다. 조립된 backend buffer의 수명은 모델과 같게 두며, mmap 및 lazy 지원은 별도 구현과 검증 전까지 거부한다. 학습 CLI는 `--qat-adapter-units`를 통해 부분 저장을 선택한다.

## llama-export-qlion

`llama-export-lora`를 출발점으로 별도 `llama-export-qlion`을 만든다. 공통 GGUF 입출력은 기존 코드를 재사용하되 LoRA의 행렬곱이나 재양자화는 수행하지 않는다. 기본 모델과 어댑터의 호환성을 위의 전체 파일 및 대체 대상별 원본 해시 규칙으로 검사한 후 대체 바이트를 복사한다. 나머지 텐서와 모델 메타데이터는 보존한다. 누락, 중복, 대상 해시 또는 형상 불일치는 출력 확정 전에 실패한다. 출력은 임시 파일을 거쳐 원자적으로 확정하며 입력과 같은 경로는 거부한다.

여러 어댑터는 같은 기준 모델에 대한 호환성 검사 후 대체 범위가 서로 겹치지 않을 때 합성할 수 있다. v1에서 범위는 전체 텐서다. 후속 부분 대체에서는 텐서, 행 및 전문가 범위를 공통 좌표로 정규화해 실제 겹침을 검사하며 전체 텐서는 그 안의 모든 행과 전문가에 겹친다. 겹치면 순서에 관계없이 거부한다. 동일 바이트도 예외로 허용하지 않는다. tied alias의 논리 이름이 달라도 같은 물리 영역이면 겹침으로 본다. 독립 학습된 변경값의 덧셈은 지원하지 않는다.

후속 단계에서는 런타임 로더가 검증된 어댑터의 텐서를 기본 모델 대신 직접 로드해 별도의 15GB급 병합 파일 없이 선택할 수 있게 한다. 부분 텐서 대체는 전체 텐서 직접 매핑만으로 해결되지 않으므로 별도의 조립 또는 overlay 설계, 백엔드 배치 및 수명 관리가 필요하다. 다중 어댑터에도 동일한 충돌 검사와 호환성 규칙을 적용한다.
## 활성 행 및 전문가 gradient

활성 행은 독립 임베딩에서 실제 조회된 행과 MoE에서 라우팅된 전문가/행을 뜻한다. tied embedding/output은 출력 projection의 gradient가 전체 어휘에 닿으므로 조회 행만 sparse로 갱신할 수 없다. tied 여부를 실제 모델 구조에서 확인하고 해당 경우 dense 경로를 사용한다. 일반 dense 행렬은 출력 전체가 사용될 수 있으므로 임의로 sparse 처리하지 않는다. 기존 sparse accumulator와 `MUL_MAT_ID` backward를 재사용해 유효한 토큰의 라우팅 인덱스만 모으고, 중복 인덱스를 합산한다. 패딩, 빈 라우트, 반복 전문가, tied embedding/output, gradient accumulation과 마지막 불완전 배치를 처리한다. 옵티마이저 상태 및 weight decay의 비활성 행 동작은 기존 dense QLion의 의미와 비교해 명시적으로 정의하고, 결과가 달라지는 최적화는 별도 모드로만 제공한다.

활성 행만 저장하는 것과 gradient 계산 자체를 생략하는 것은 다르다. 구현은 실제 outer product와 중간 버퍼 크기도 활성 집합에 비례하는지 검증한다. 용량 초과 시 안전하게 확장하거나 정확한 dense 경로로 fallback하고 조용히 gradient를 버리지 않는다. CPU를 수치 기준으로 하고 CUDA 등 각 백엔드는 지원 여부와 fallback을 명시한다. 약 6M Gemma 4 MoE 모델을 만들어 Quadro P620에서 학습하고, 같은 조건의 6M dense 모델과 시간 및 peak 메모리를 비교한다. MoE가 비슷하거나 더 나은 효율을 보이는 것을 목표로 하며, 측정 조건과 미달 원인을 기록한다.

## K/V 및 MoE backward

`attn_k`, `attn_v`를 각각 단독 학습 대상으로 선택해 gradient가 유한하고 0이 아닌지, loss의 유한 차분과 일치하는지 확인한다. 일반 attention과 flash attention, KV cache on/off, microbatch 경계와 공유 KV 레이어를 따로 시험한다. 현재 분리된 과거 KV에 대한 gradient가 전체 시퀀스 학습 목적에 필요한 경우, 현재 토큰과 과거 캐시의 소유권 및 수명, 재계산 또는 저장 비용을 명시한 경로를 구현한다. 기존 추론 캐시 동작을 변경하지 않는다.

MoE는 router, shared/dense FFN, 선택된 전문가의 gate/up/down을 구분한다. Gemma 4의 fused gate-up 형상 및 전문가 스케일을 포함한다. 라우팅 선택은 이산적이므로 선택 인덱스에 gradient를 만들지 않고, 선택된 경로의 값과 router 확률에 필요한 gradient를 검증한다. 작은 참조 연산 및 유한 차분과 비교하고, 활성 전문가만 바뀌는지와 비활성 전문가 상태의 의미를 검사한다. 양자화 타입별 CPU 지원을 먼저 확보한 뒤 각 GPU 경로를 검증한다.

## Static training graph

고정 최대 KV 용량과 고정 마스크/입력 형상을 사용하고 실제 유효 길이, 위치, 행 인덱스 및 loss mask는 매 실행 갱신하는 방안을 우선 검토한다. 패딩은 attention과 loss에서 완전히 마스킹해야 한다. 시퀀스 길이, 병렬도, 마이크로배치, 타입 또는 라우팅 버퍼 용량이 달라지면 해당 형상의 그래프를 새로 만든다. optimizer step, 누적 횟수, RNG 및 KV 초기화가 실행 간 올바르게 갱신되는지 확인한다. 고정 버퍼의 VRAM 비용과 추가 연산을 동적 그래프와 비교하고, 불리하거나 지원되지 않는 경우 기존 동적 경로로 돌아간다. 메모리 추정과 유효 길이 검사를 allocation 전에 수행한다.
