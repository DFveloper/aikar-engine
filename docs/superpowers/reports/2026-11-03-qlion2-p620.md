# QLion2 P620 validation and bounded CUDA workspace

Later implementation of the three remaining scopes is documented in [fixed-KV, compact routing, and core-loader validation](2026-11-03-qlion2-three-scopes.md). Remaining-work statements below describe the earlier implementation.

Date: 2026-11-03 (Asia/Seoul). Base commit: `cd0adf4a5`. This extends the [CPU follow-up](2026-11-02-qlion2-followup.md). P620 access is now available. The time-ratio goal remains unmet; this report does not mark the complete A/B design as finished.

## Implementation

- Fixed nondeterministic CUDA expert routing. The old atomic scatter did not sort routes, despite its header comment. Two identical dynamic MoE runs differed in 115 final tensors; losses first diverged at step 4. Each expert now has a block that scans input tiles and uses a shared prefix sum to emit routes in input order. Integer counting/prefix offsets remain unchanged. The same helper serves routed dX and QLion expert updates, including duplicate routes and route ranks. It uses no additional device allocation or warp-size assumptions. Work is proportional to experts times routes; this is a correctness tradeoff, not a claim of active-only routing cost.
- Added bounded F32 conversion for large contiguous, non-Q4 quantized CUDA `OUT_PROD` inputs. Existing conversion functions and SGEMM process reduction tiles with at most 64 MiB of conversion scratch. Transposed F32 inputs, grouped batches, broadcasting, and the original accumulation beta are preserved. Small inputs retain their previous path; Q4_0 retains its existing half-precision tiled path. The generic path applies when one decoded row fits the workspace. It changes reduction grouping, so numerical equivalence is tested rather than promising byte identity with the old whole-tensor GEMM.
- Extended the existing integration script with physical GPU identity, 10 ms NVML whole-device memory sampling, separate CPU/GPU comparison fields, GPU graph-reuse fallback checks, and a partial placement test with `--no-op-offload`. No Python dependency was added. NVML usage includes other processes and driver reservations; sampling can miss shorter peaks.

## Actual 26B hybrid training

Source: `/mnt/openwebui/AIKAR/Lumen-3.8-Pulsar/gemma-4-26B_q4_0-it.gguf`. The successful command is retained in `/tmp/qlion-p620-validation/26b-tiled-gpu.json`. Relevant options:

```sh
--optimizer qlion2 --quant-type q4_0 \
--qat-targets blk.0.attn_k.weight,blk.0.attn_v.weight,blk.29.ffn_down_exps.weight \
-c 256 -b 256 -ub 256 -ngl 0 --no-op-offload \
--override-tensor 'blk\.0\.attn_(k|v)\.weight=CUDA0,blk\.29\.ffn_down_exps\.weight=CUDA0' \
-t 8 -tb 8 --dataset-threads 2 --epochs 2 --val-split 0 \
--learning-rate 0.01 --lr-scheduler constant --qat-out '' \
--qat-adapter-out /tmp/qlion-p620-validation/26b-tiled-gpu-adapter.gguf \
--qat-adapter-units experts --save-every 0 --save-first-at 0 --verbosity 5 --verbose-loss
```

The three selected GPU tensors occupy 149,225,472 bytes. The model's remaining weights stay on CPU; this is not a fully GPU-resident 26B run. Both optimizer steps completed, with ten supervised tokens each: **48.158589 and 47.085088 seconds**. Total elapsed time including original hashing and adapter publication was **291.56 seconds**. Peak process RSS was **17,792,272 KiB**; sampled whole-device peak was **1,612,775,424 bytes (1.50 GiB)**. This differs in targets and microbatch size from the previous CPU smoke, so it is not a controlled CPU/GPU speed comparison or a quality evaluation.

The nonempty v2 adapter is **51,455,360 bytes (49.07 MiB)**, with 51,093,504 payload bytes:

| Tensor | Changed units | Payload bytes |
| --- | ---: | ---: |
| Block-0 K | 2,048 rows | 3,244,032 |
| Block-0 V | 2,048 rows | 3,244,032 |
| Block-29 expert down | 40 / 128 experts | 44,605,440 |

The adapter was then applied at runtime to the original 26B model using the same scoped GPU placement, resident loading (`--load-mode none --lazy-mode off --no-repack`), seed 42, prompt `hi`, and two generated tokens. Completion exited successfully (`26b-runtime.log` and `26b-runtime.time`); no new full merged model was required. The small-model GPU suite separately compares merged/runtime inference exactly. This is a functional inference check, not a quality claim.

Independent decoding found finite weights in all payloads. Changed units are not a count of all routed experts or all nonzero gradients. Optimizer momentum/residual remain full selected-tensor states.

Three earlier attempts failed and produced no successful adapter: ordinary `-ngl 1` placed the large output on GPU and exhausted memory in whole-tensor conversion; explicit tensor placement with automatic host-operation offloading attempted a roughly 16 GiB scheduler buffer; explicit placement with `--no-op-offload` still exhausted memory in the unbounded non-Q4 `OUT_PROD` conversion. The first failed process was terminated while handling its core dump; later trials disabled core dumps only for their child process. The successful result requires both scoped placement and bounded conversion.

## Remaining scope

The P620 time-ratio target is not met. Reducing launch/synchronization count and shared/routed FFN dispatch is a better next performance target than removing route determinism or suppressing gradients. Larger real packed batches are worth comparing with matched supervised token counts, but should not be called a win based on padding or changing the trainable set.

General fixed-KV microbatch graph reuse, actual-route-sized 26B Q8 state beyond conservative routing bounds, mmap/lazy adapter overlays, direct core-loader integration, and GPU implementations of compact Q8 accumulation remain outside this implementation. The existing CPU-compatible shape reuse and GPU fallback remain in place. Large generic CUDA tiling passes numerical reference tests; it does not guarantee the old reduction's exact optimizer trajectory on other GPU architectures.
