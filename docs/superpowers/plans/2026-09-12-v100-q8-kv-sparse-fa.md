# V100 Direct Q8_KV Sparse Flash Attention Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a direct Q8_KV sparse Flash Attention decode kernel for the Gemma 4 D256/V256/GQA2 sliding-window layers on V100.

**Architecture:** SWA graph nodes publish `min(n_swa, current KV rows)` as the sparse KV upper bound. CUDA compacts the mask, gathers Q8_KV rows, dequantizes them directly into the existing half shared-memory MMA tiles, and runs the existing Volta MMA math. Unsupported and full-attention nodes retain the current vector/tile paths.

**Tech Stack:** C++17, CUDA C++, ggml CUDA Flash Attention, Volta tensor-core MMA, llama-server runtime verification

**Spec:** `docs/superpowers/specs/2026-09-12-v100-q8-kv-sparse-fa-design.md`

## Global Constraints

- Target compute capability is exactly 7.0 for the new direct Q8_KV path.
- Initial supported shape is decode `Q->ne[1] == 1`, DKQ=256, DV=256, and GQA ratio 2.
- Both K and V must use `GGML_TYPE_Q8_KV`.
- Do not allocate or populate a full F16 KV staging buffer.
- Full-attention layers and unsupported inputs keep existing behavior.
- Do not add a file under `tests/`.
- Do not commit without explicit user approval.

### Task 3: Load Q8_KV rows directly into MMA shared memory

**Files:**
- Modify: `ggml/src/ggml-cuda/fattn-mma-f16.cuh`

**Interfaces:**
- Consumes: `const char *` K/V bases, byte row strides, sparse row indices, and `block_q8_kv` with `QK8_KV == 64`.
- Produces: the existing swizzled `half2` K/V shared tiles expected by `flash_attn_ext_f16_process_tile`.

- [ ] **Step 1: Add a typed sparse Q8 loader**

For each selected row and element pair, load `block_q8_kv`, multiply two signed bytes by the F16 block scale, convert to `half2`, and store through the existing swizzle calculation. Invalid padded indices store zero.

```cpp
const block_q8_kv & block = reinterpret_cast<const block_q8_kv *>(row)[k2 / (QK8_KV/2)];
const int iq = 2*(k2 % (QK8_KV/2));
const half2 value = make_half2(__half2float(block.d)*block.qs[iq], __half2float(block.d)*block.qs[iq + 1]);
```

- [ ] **Step 2: Preserve byte strides in the global Q8 path**

Keep `nb11` and `nb21` as byte strides for Q8_KV. Divide them by `sizeof(half2)` only for the existing F16 loader. Do not cast Q8 storage to `half2 *` before row addressing.

- [ ] **Step 3: Thread the Q8 template flag through process and kernel selection**

Select the Q8 loader only when `use_sparse` and both KV tensors are Q8_KV. Dense and non-Q8 instantiations compile to the existing code.

- [ ] **Step 4: Guard padded V100 columns**

Audit Q, sink, destination, metadata, and fixup accesses for logical heads beyond `ne02`. Add predication or zero inputs where physical ncols2=32 exceeds GQA2, without divergent synchronization.
