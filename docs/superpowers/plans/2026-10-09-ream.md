# REAM implementation and validation

User specification is the design authority. Implement inline, without commits or upstream submissions.

1. Preserve REAP and add separately selected REAM to aikar-prune.
2. Port saliency-ordered capacity-limited pseudo-grouping, normalized Euclidean neuron costs and exact Hungarian assignment. Reuse existing REAP saliency unchanged. Replace zero saliency as in reference, with an explicit all-zero fallback.
3. Use GGML GELU gated FFN evaluation on chunked Gemma4 MoE inputs captured from the existing eval callback. Keep router and expert inputs distinct. Store sampled hidden activations on disk, not all expert/token outputs in RAM.
4. Merge gate/up rows and down columns with FP32 accumulation, preserving singletons byte-for-byte. Fold per-expert scales into effective weights and reset merged scales to one.
5. Replay calibration with merged preceding layers and unchanged subsequent layers. Recreate the inference context after each layer; set the internal existing expert mask for processed layers without changing the public REAP profile API.
6. Stream compact GGUF using center rows/slices sorted by original ID. Preserve Top-K and shared experts. Store every source ID's group and center in GGUF metadata and a report. Reject unsupported formats, shapes, biases, architectures and MTP before output.
7. Extend test-moe-prune, compile and run existing and new tests. Validate synthetic model in separate processes. Run actual Lumen dry-run and feasible inference; report any large-model compression and benchmark gaps honestly.

Reference differences to disclose: no PCA initially (exact full weight distance), deterministic common activation sample instead of independent samples, preserved engine REAP gate semantics instead of reference's double-gating behavior, token-weighted output means instead of equal batch means.

Memory: one source expert, center, FP32 accumulator, two sampled hidden matrices, dense Hungarian cost and bounded FFN graph per layer; full inference model is CPU-resident. Inputs and sampled activations are temporary files under an exclusive work directory. Dry-run reports workspace separately from inference model and device buffers.
