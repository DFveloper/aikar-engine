# V100 tensor-parallel recovery

Use two NVLink-connected V100 16 GiB GPUs, CUDA 12.4 and GCC 13. The launcher selects physical GPUs 0 and 1, tensor split 1:1 and full model offload. Training uses the meta backend's F32 butterfly reduction with CUDA peer copies across NVLink; inference keeps the existing backend collective selection. Override `CUDA_VISIBLE_DEVICES` if the GPUs have different physical indices. A third display GPU is excluded.

```bash
bash scripts/logit-distillation/v100.sh build
bash scripts/logit-distillation/v100.sh download
bash scripts/logit-distillation/v100.sh teacher
bash scripts/logit-distillation/v100.sh infer
bash scripts/logit-distillation/v100.sh train --dry-run
bash scripts/logit-distillation/v100.sh train
```

`BUILD_DIR`, `BIN_DIR`, `CUDA_HOST_COMPILER`, `TEACHER`, `STUDENT`, `DOWNLOAD_DIR`, `CACHE_DIR`, `DATA`, `CACHE`, `OUTPUT`, `CTX`, `UBATCH`, `EPOCHS`, `LR` and `RECOMPUTE` are environment overrides. `PROMPT` and `TOKENS` control completion. Additional arguments are passed to the selected executable. `download` uses the Hugging Face `hf` CLI and resumes interrupted downloads. `build` configures SM70 and F16 Flash Attention kernels. No model weights are converted to hardware FP4 instructions.

The launcher enables CUDA peer access and sets `GGML_CUDA_ALLREDUCE=none` for training by default. Here `none` disables the custom CUDA collective and selects the meta backend's peer-copy reduction; tensor parallelism and reductions remain active. `GGML_CUDA_ALLREDUCE=internal` selects the host-staged collective. Set `GGML_CUDA_P2P=0` to unset the backend's presence-based switch. Training disables CUDA graph capture by default; `GGML_CUDA_DISABLE_GRAPHS=0` in this launcher enables capture. Inference keeps the backend's graph default.

The CUDA build was copied to persistent `build-v100/bin`, the launcher default, so it survives reboot. The launcher sets its library search path for these binaries. The temporary CMake build tree is `/tmp/lumen-v100-build`; it can be discarded after copying the binaries. Model paths default to `/mnt/openwebui/AIKAR/Lumen-3.8-Pulsar/Test.gguf` (Gemma 4) and `Lumen-3.8-Pulsar-base.gguf` (Lumen4Exp).

## Architecture and memory

Global attention layers are 5, 11, 17, 23 and 29, zero-based. Layer 5 is the only global KV owner. Layers 11, 17, 23 and 29 all reuse layer 5. The temporary independent-layer-17 override and its GGUF metadata support have been removed.

Only Q and attention output weights of layers 11, 17, 23 and 29 train, eight tensors in total. Layer 5, SWA attention and MoE weights stay frozen. `targets.sh` defines the defaults. Training saves a separate adapter and does not overwrite the base GGUF.

Global KV uses the per-16 FP4 cache, including during recovery. Inference dequantizes packed cache values on CUDA for F16 Flash Attention. Training uses FP4 quantization in the forward graph with straight-through gradients. SWA uses F32 cache storage during training because the differentiable cache path requires F32. The launcher uses context 1024, microbatch 128, retained activations (`RECOMPUTE=off`) and dynamic training graphs. Set `RECOMPUTE=on` to save VRAM when increasing context or microbatch size. Past microbatches are detached at the cache boundary, so this is truncated attention backpropagation. FP4 storage does not make all backward activations FP4.

The KL loss needs the full student vocabulary. `^output\.weight$` matches only the vocabulary head and places it on CUDA0 to keep vocabulary logits mirrored for the existing top-k plus tail loss; the transformer layers remain tensor parallel. Measure peak VRAM on both devices before increasing context or microbatch size. The single-owner architecture completed a short real-model training run within 16 GiB per GPU; this does not establish the peak memory of a full recovery run.

The CPU KL finite-difference tests, tensor-parallel dense/MoE gradient comparisons, grouped-query attention gradient comparisons and layer-source regression pass. The CPU meta backend also completed a full 30-layer recovery step with recomputation and microbatch 128. Fourteen accumulation tests check cache reshape directions, partial cache updates, fused gate/up and QKV gradients, and zero-initialized accumulation against a scalar reference. ## Optimization measurements

The 2026-11-06 measurements use the same real student, cached teacher targets, context 1024, microbatch 128, two training windows, one validation window, eight Q/output targets, LR 1e-5 and one epoch. Both V100s retained the user's 150 W limit and approximately 997 MHz clock. These short runs measure execution, not recovery quality.

| Collective | Activation recompute | Input tokens/s | Validation KL |
| --- | --- | ---: | ---: |
| Internal, host staging with BF16 wire values | on | 102.897 | 2.502555 |
| F32 peer-copy butterfly | on | 110.703 | 2.499084 |
| F32 peer-copy butterfly | off | 121.507 | 2.507399 |

The third configuration is the training launcher default. A repeat with those defaults reached 121.847 input tokens/s, reproduced both training losses and validation KL exactly, and wrote a byte-identical adapter containing all eight updated targets. Its sampled peak VRAM was 10,856/11,530 MiB, versus 10,246/10,920 MiB for the earlier internal/recompute run. The peer-copy path removes host staging and the collective's BF16 round trip, so outputs are not bit-identical to the internal path. Recompute and graph fusion choices also changed the measured losses slightly. Do not interpret the speed difference as proof of equivalent recovery quality.

Inference uses the existing collective by default because separate 128-token measurements did not favor the peer-copy fallback: median Lumen decode throughput was 81.125 tokens/s with internal reduction versus 73.685 with peer copies; Gemma was 80.330 versus 73.045. Each is only two runs with CUDA graphs disabled and a raw completion prompt. They establish the configuration choice for this experiment, not output-quality equivalence or a general inference benchmark.

The nvprof report attributes most GPU time to GEMM and routed-weight dequantization. Retaining activations avoids replaying the forward work. Nsight Systems 2023.4 could not import its trace because of event-order errors; nvprof statistics were collected instead. The initial no-adapter profiling attempt finished training but hit an assertion in full-model export, so successful measurements use the tested adapter export path.

SHA-256 now processes full 64-byte blocks directly, copying only partial blocks. It preserves all file hashes and base-file validation. In three interleaved 512 MiB trials, median hashing throughput increased from 159.357 to 187.445 MiB/s. Padding boundaries, fragmented updates, zero-length updates and unaligned input pass the adapter test suite; 1,578 additional streamed cases matched Python hashlib with UBSan enabled. The optimized full short runs, including base hashing and adapter export, took 184.87 and 185.69 s; the earlier short run took about 212 s. Most remaining startup/save time is still hashing the 14 GB base twice.

Reproduce the training comparison after downloading the teacher cache:

```bash
# Prior communication and memory settings
GGML_CUDA_ALLREDUCE=internal RECOMPUTE=on MAX_WINDOWS=2 VAL_WINDOWS=1 EPOCHS=1 \
  OUTPUT=/tmp/lumen-internal.adapter.gguf bash scripts/logit-distillation/v100.sh train
# Optimized defaults
MAX_WINDOWS=2 VAL_WINDOWS=1 EPOCHS=1 OUTPUT=/tmp/lumen-peer.adapter.gguf \
  bash scripts/logit-distillation/v100.sh train
```

Logs, `opt-metrics.json`, `opt-nvprof-none.csv`, hashing benchmarks and VRAM samples are under `build-distill-cpu/lumen-v100-validation`. To run the F32 peer-collective gradient checks, use `GGML_CUDA_ALLREDUCE=none CUDA_VISIBLE_DEVICES=0,1 build-v100/bin/test-logit-distillation --cuda` with the runtime library path set as in the launcher.
